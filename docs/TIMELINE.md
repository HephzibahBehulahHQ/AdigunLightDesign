# Cue timeline

Effect eligibility uses each fixture profile's active mode channels, including for legacy files with extra stored properties. Fixed wash/strip modes do not acquire motion from stale pan/tilt properties. Newly created fixtures initialize only their declared channels. These are application-authored virtual modes, not verified manufacturer profiles.

Channel keyframes are optional `{fixtureId, property, time, value}` records in `channelKeyframes`. The editor adds/replaces a channel's frame at a time or deletes an entry. Only channels already captured in the cue are allowed. Times must lie within the cue and values must be integer DMX bytes; duplicate channel/time records and more than 4096 entries are rejected. Frames interpolate linearly from the source value at time zero, or snap to an explicit zero-time frame, then hold the final value. A channel with frames overrides its default fade/hold/fade-out envelope; other channels keep that envelope. These edits are undoable and native imports preserve them. Curve handles and drag editing remain unimplemented; browser interaction remains unverified.

Cues optionally fade back to their starting fixture values at the end. `fadeOut` defaults to zero for legacy files; delay + fade-in + fade-out must fit the duration. The remaining interval holds target values. Fade-out returns to the cue's source values, which may be nonzero, rather than forcing blackout. Capture/edit controls expose this timing and display the saved hold interval. Boundary keyframe records and native validation preserve the setting. Explicit channel keyframes take precedence as described above.

The virtual pan/tilt-circle preset changes only existing pan/tilt properties, leaves fixed fixtures and dimmer/color values unchanged, and offsets phase by fixture order. Its editor preview uses channels 64–192. Motion is artistic and uncalibrated; there is no motor speed, collision or physical-output guarantee. It shares effect Pause/Resume and Stop and does not save changes into the project.

Scheduled tracks are independent of Play sequence. Assign a cue a track name and nonnegative start time, then use Play tracks. Legacy cues default to consecutive positions on Main. Same-track overlaps are rejected; different tracks may overlap. Tracks evaluate independently from the captured source scene and hold their completed values through gaps. When tracks target the same fixture channel, the later track in first-appearance order wins that channel. Arrangement playback supports Pause/Resume, Stop, the loop preference and a keyboard-accessible seek slider. Committing a seek opens a paused arrangement preview; Resume continues from that position. All editor transactions validate the complete document before saving. Native files retain optional cue `trackId` and `startTime` fields. The separate sequence lane still follows stored cue order. Cue timing and scheduling controls are grouped in a collapsible section; the transport and lanes remain visible.

Fixture groups store named sets of existing fixture IDs in the optional `fixtureGroups` project field. Older version-1 files without groups remain valid. The group editor creates, edits and deletes groups through undoable transactions. Edit group loads its name and membership; Save group updates that identity, while New group resets the form. Capture group limits a new cue's snapshot to that group; other fixtures retain their values during evaluation. Editing or deleting a group preserves already captured cues. Native import validates group identities and membership.

The sequence lane uses cumulative start times and duration-proportional blocks, with a seconds ruler and a moving sequence playhead. It displays a minimum 30-second span and expands for longer sequences. The separate scheduled-track lanes show simultaneous cues. Layout arithmetic is tested; rendered visual fidelity is unverified.

Duplicate cue inserts an independent copy immediately after the selected cue in stored order and selects it. For explicitly timed tracks, the copy is scheduled after the track's final cue to avoid overlap. Delete cue removes the selection and selects the nearest remaining cue. Both stop previews and use document undo/redo; deleting the final cue is supported. Captured targets and keyframes remain independent between copies.

The sequence transport includes a persistent loop preference and a keyboard-accessible seek slider. Committing a seek starts a paused sequence preview at that position; Resume continues from there. Looping restarts from the captured source scene on each cycle. These controls apply to the full stored cue sequence. Seeking does not edit project data. Browser interaction remains unverified.

Virtual effect previews provide a cosine dimmer pulse and an ordered dimmer chase with an editable cycle of 0.1–120 seconds. Both loop until Stop or a document mutation. They evaluate cloned fixture data and change only rendered preview intensity; they do not save effect settings, alter cue snapshots, or transmit hardware output. Deterministic phase, wraparound, bounds and immutability have domain tests; browser playback remains unverified.

M5 stores cue snapshots separately from renderer state. A cue records fixture property targets, duration, delay, fade metadata and keyframe boundary records. Playback interpolates from a snapshot of the current fixtures to the stored target and sends preview values to the renderer. Playback does not overwrite or save the project's fixture values. Stop and completion restore the saved scene on the next render.

The controls capture cues with editable duration, fade and delay, select a cue, edit its name and timing, play it, and stop it. Cue edits preserve captured fixture targets and use project undo/redo. Import, undo, redo and document mutations stop playback. Delay holds the starting values; a zero-length fade switches at the scheduled delay. Timing must fit within the cue duration. The displayed virtual DMX frame represents saved fixture values, not the animated preview.

Play sequence opens the 3D preview and evaluates cues in their stored order. Each cue starts from the previous cue's completed fixture values. Boundary transitions, completion, empty sequences and preservation of source data have automated coverage. Stop cancels the sequence and restores the saved scene.

Earlier/Later controls move the selected cue one position in the stored sequence. Boundary controls are disabled. Reordering is undoable, preserves cue snapshots and stops any running preview.

Pause/resume freezes the elapsed playback clock for cues, sequences and effect previews. Resume excludes paused wall time; repeated pause/resume requests do not shift timing. Stop still restores saved fixture values. Domain clock behavior has automated coverage. Continuous drag preview and hardware output remain unimplemented. The implementation does not send DMX to physical devices, synchronize a console or claim real-time hardware timing. Browser interaction and visual acceptance remain unverified.
